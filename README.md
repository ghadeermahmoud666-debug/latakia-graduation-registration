# منصة التسجيل لحفلات التخرج – جامعة اللاذقية

مشروع React + Vite باللغة العربية (RTL)، مع Supabase كقاعدة بيانات وتخزين خاص، وCloudflare Pages لنشر الواجهة. صُمم كنموذج أولي عملي قابل للنشر بعد إضافة مفاتيح المشروع وضبط بيانات الدفع.

## الوظائف الموجودة

- تسجيل الطالب بالاسم الثلاثي، الرقم الجامعي، القسم، الاختصاص، وعدد المرافقين.
- احتساب الرسوم من إعدادات الفريق، وليس من قيمة يرسلها المتصفح.
- رفع إيصال PDF إلى مساحة تخزين خاصة لا يمكن للطلاب قراءة ملفاتها مباشرة.
- إنشاء كود متابعة عشوائي للطلب بعد حفظه بنجاح.
- تتبع حالة الطلب باستخدام كود المتابعة والرقم الجامعي.
- دخول للموظفين، قائمة بالطلبات، بحث وتصفية، عرض إيصال مؤقت الصلاحية، قبول أو رفض مع سبب، وتصدير CSV.
- إعدادات رسوم الطالب والمرافقين، الحد الأقصى للمرافقين، حساب شام كاش، صورة QR، وفتح/إغلاق التسجيل.
- صلاحيات قاعدة البيانات تمنع الزوار من قراءة طلبات الآخرين، وتحصر مراجعة الطلبات وتعديل الإعدادات بفريق مخوّل.

## الأدوات

- React + Vite
- Supabase (Postgres + Auth + Storage + Edge Functions)
- Cloudflare Pages (واجهة ثابتة)

## 1. إنشاء مشروع Supabase

1. أنشئ مشروعاً من [supabase.com](https://supabase.com/).
2. افتح **SQL Editor** وشغّل محتوى `supabase/migrations/001_init.sql` كاملاً.
3. من **Project Settings → API** انسخ Project URL و`anon`/publishable key.
4. احتفظ بمفتاح `service_role` سرياً تماماً؛ لا تضعه في ملف `.env` الخاص بالواجهة، ولا ترفعه إلى GitHub.

> يبدأ الموقع والتسجيل مغلقان (`registration_open = false`) حتى يضبط الفريق الرسوم والحساب ثم يفتح التسجيل من لوحة التحكم.

## 2. نشر الوظائف الخلفية

ثبّت Supabase CLI ثم سجّل الدخول واربط المجلد بالمشروع:

```bash
npm install
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy submit-application
supabase functions deploy track-application
```

استخدم `YOUR_PROJECT_REF` من عنوان مشروع Supabase. تتوفر عادةً متغيرات `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` للوظائف المنشورة في بيئة Supabase. إن طلبت بيئتك ضبطها يدوياً، أضفها كـ **Secrets** للوظائف من واجهة Supabase/CLI، ولا تضعها في الواجهة.

## 3. تشغيل الواجهة محلياً

```bash
cp .env.example .env.local
```

عدّل `.env.local` وأدخل القيم الحقيقية:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
```

ثم شغّل:

```bash
npm install
npm run dev
```

ولفحص نسخة الإنتاج محلياً:

```bash
npm run build
npm run preview
```

مفاتيح `VITE_*` تكون متاحة في المتصفح؛ لا تضع فيها مطلقاً مفاتيح `service_role` أو كلمات سر الموظفين.

## 4. إعداد أول مدير وإضافة فريق المراجعة

1. من **Authentication → Users** في Supabase أنشئ حساباً لكل موظف (يمكن تعطيل تسجيل المستخدمين العامين من إعدادات Auth).
2. انسخ UUID الخاص بكل مستخدم.
3. في SQL Editor أضف المستخدمين المخوّلين، على سبيل المثال:

```sql
insert into public.staff_roles (user_id, role)
values
  ('UUID-OF-ADMIN', 'admin'),
  ('UUID-OF-REVIEWER', 'reviewer');
```

4. يدخل الموظف من زر **دخول الفريق** باستخدام حسابه.
5. من **إعدادات التسجيل** أدخل عنوان الحفل والرسوم الفعلية وحساب شام كاش، وارفع صورة QR إن لزم، ثم افتح التسجيل.

لا تنشئ حساباً عاماً للطلاب؛ حسابات Auth مخصصة لفريق المراجعة فقط.

## 5. نشر الموقع مجاناً على Cloudflare Pages

1. ارفع مجلد المشروع إلى مستودع GitHub خاص أو عام بعد التأكد من عدم رفع `.env.local`.
2. أنشئ مشروع **Pages** في Cloudflare واربطه بالمستودع.
3. إعدادات البناء: **Build command:** `npm run build`، و**Build output directory:** `dist`.
4. في إعدادات المشروع → Variables/Environment variables أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` لبيئة Production (وأيضاً Preview إن أردت).
5. أعد تشغيل عملية البناء بعد إضافة المتغيرات.

لا تحتاج إلى شراء نطاق خاص كي يعمل الموقع؛ سيعطيك Cloudflare عنواناً فرعياً مجانياً. النطاق الخاص اختياري وقد تكون له كلفة.

## ملاحظات مهمة قبل فتح التسجيل للعامة

- **التحقق من الدفع يدوي في هذه النسخة:** يحوّل الطالب إلى شام كاش ثم يرفع الإيصال؛ لا تؤكد المنصة استلام المال تلقائياً. يمكن دراسة التكامل عبر API الرسمي لشام كاش بعد قبول طلب التكامل والحصول على بيانات موثقة، ويجب أن يكون التحقق من الخادم لا من المتصفح.
- أضف حماية من الإرسال الآلي (مثل Cloudflare Turnstile أو آلية تحديد معدل الطلبات) قبل نشر رابط التسجيل على نطاق واسع. الوظائف تتحقق من الحقول والملف وحجمه، لكن النسخة الأولية لا تتضمن CAPTCHA/Rate Limiting.
- فعّل MFA لحسابات فريق التنظيم إن توفر، واستخدم كلمات مرور فريدة، ولا تشارك حساب الموظف بين عدة أشخاص. أعطِ أقل عدد ممكن من الأشخاص صلاحية المراجعة.
- إيصالات الدفع بيانات حساسة. اتفقوا على مدة الاحتفاظ بها ومن يملك حق الاطلاع عليها واحذفوها عندما لا تعود لازمة. يمكن إعداد نسخة احتياطية وخطة استعادة إذا كانت الحفلات مهمة تشغيلياً.
- خطة Supabase المجانية مناسبة للتجربة/الإطلاق الصغير، لكنها ليست ضماناً مجانياً دائماً: لها حدود تخزين ونقل بيانات وقد تتوقف المشاريع قليلة النشاط مؤقتاً. راجع الحدود الحالية قبل موسم التسجيل.
- قبل نشر الموقع باسم الاتحاد، تأكد من موافقة الجهة المخولة على الاسم والشعار وآلية جمع بيانات الطلاب وشروط الدفع والاسترداد.
